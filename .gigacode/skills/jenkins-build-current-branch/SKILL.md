# Запуск Jenkins для текущей ветки executor

## Контракт запуска

Запускать только следующую параметризованную job:

```text
https://sbt-jenkins.sigma.sbrf.ru/job/digital_assisitant_b2c/job/JAVA/job/router-executor/job/Deploy_Job/
```

Передавать в Jenkins ровно два параметра:

```text
REPO_BRANCH=<current_branch>
CONFIG_BRANCH=<current_branch>
```

Оба значения должны точно совпадать с именем текущей локальной Git-ветки. Остальные параметры Jenkins не передавать и не переопределять: они должны остаться со значениями по умолчанию.

## Порядок выполнения

### 1. Проверить репозиторий и текущую ветку

Выполнить из текущей директории:

```bash
repo_root="$(git rev-parse --show-toplevel)"
current_branch="$(git branch --show-current)"
origin_url="$(git remote get-url origin)"
```

Проверить в `${repo_root}/settings.gradle.kts`:

```text
rootProject.name = "dab2c-executor"
```

Остановиться без запуска job, если:

- текущая директория не относится к Git-репозиторию;
- это не проект `dab2c-executor`;
- текущая ветка пуста или репозиторий находится в detached HEAD;
- remote `origin` отсутствует;
- имя ветки, репозиторий или job определены неоднозначно.

Сохранить точное имя ветки как `current_branch`. Не переключать и не переименовывать ветку.

### 2. Проверить удалённую ветку

Проверить через Git и Bitbucket MCP, опубликована ли `current_branch` в `origin`. Допустима дополнительная read-only проверка:

```bash
git ls-remote --exit-code --heads origin "refs/heads/${current_branch}"
```

Если ветка отсутствует, запланировать её публикацию после подтверждения пользователя. Если ветка уже существует, не выполнять `push` только ради запуска сборки.

### 3. Проверить Jenkins job

Через Jenkins MCP прочитать job и её параметры. Проверить:

- точный URL и полное имя job;
- что job является параметризованной;
- наличие `REPO_BRANCH` и `CONFIG_BRANCH`;
- наличие действия Jenkins MCP для параметризованного запуска.

Не выбирать другую job по похожему имени. Если доступно только чтение, остановиться и сообщить, что CLI не предоставляет разрешённое действие Jenkins MCP для запуска. Не заменять его браузером, `curl` или прямым HTTP-запросом.

### 4. Подготовить preview

Сформировать параметры:

```text
REPO_BRANCH=<current_branch>
CONFIG_BRANCH=<current_branch>
```

Проверить перед запуском:

```text
REPO_BRANCH == CONFIG_BRANCH == current_branch
```

Показать пользователю:

- точный URL Jenkins job;
- URL `origin`;
- текущую ветку;
- два передаваемых параметра и их значения;
- потребуется ли `git push -u origin <current_branch>`.

Отдельно указать, что другие параметры не передаются и останутся со значениями Jenkins по умолчанию.

### 5. Получить подтверждение

До внешних действий запросить однозначное подтверждение preview. Если пользователь уже подтвердил запуск после просмотра этих точных значений в текущем диалоге, повторное подтверждение не требуется.

### 6. При необходимости опубликовать ветку

После подтверждения, только если точная ветка отсутствует в `origin`, выполнить:

```bash
git push -u origin "${current_branch}"
```

Повторно проверить:

```bash
git ls-remote --exit-code --heads origin "refs/heads/${current_branch}"
```

При ошибке `push` или отсутствии ветки после проверки остановиться и не запускать Jenkins. Не использовать `--force`, `--force-with-lease`; не публиковать другие ветки или теги.

### 7. Запустить job

Через Jenkins MCP запустить точную job, передав ровно:

```text
REPO_BRANCH=<current_branch>
CONFIG_BRANCH=<current_branch>
```

Не добавлять в запрос `PLAYBOOKS` или любые другие параметры. После запуска получить и показать:

- номер сборки;
- прямую ссылку на сборку;
- переданные значения `REPO_BRANCH` и `CONFIG_BRANCH`;
- текущий статус.

Не ждать завершения сборки, если пользователь отдельно не попросил дождаться и проверить результат.

## Ограничения

- Не запускать этот скилл для другого репозитория.
- Не выполнять `commit`, `merge`, `rebase` или переключение ветки.
- Не изменять файлы проекта.
- Разрешён только условный `git push -u origin <current_branch>` для отсутствующей одноимённой ветки после подтверждения пользователя.
- Не раскрывать tokens, cookies, пароли и другие учётные данные.
- Не подменять Jenkins MCP или Bitbucket MCP браузером и прямыми HTTP-запросами.
- При любой неоднозначности остановиться до внешнего действия и запросить уточнение.
